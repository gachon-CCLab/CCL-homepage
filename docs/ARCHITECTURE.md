# React 구조

## 앱과 콘텐츠

- React 19와 TypeScript를 사용합니다. `src/main.tsx`가 현재 URL에 맞는 페이지 모듈을 불러옵니다.
- 공통 헤더·푸터·레이아웃은 `components/layout`, 사진 확대는 `components/media`에서 관리합니다.
- 메뉴·사진 뷰어 상태는 React의 state, ref, context와 이벤트로 관리합니다. 전역 DOM 검색으로 페이지에 이벤트를 붙이던 이전 스크립트는 실행하지 않습니다.
- 멤버·세미나는 타입이 있는 데이터와 재사용 카드·그룹 컴포넌트로 분리했습니다. 현재/이전 멤버 수와 이동 링크는 데이터에서 계산합니다.
- 과거 연구·논문·갤러리의 본문은 구조화된 노드 데이터로 유지합니다. `RichContent`가 이를 React 요소와 `PhotoLink`로 렌더링하며 HTML 문자열 삽입을 사용하지 않습니다. 원본 문장·표·이미지·영상·앵커를 유지하기 위한 구성입니다.
- 페이지 모듈은 명시적인 동적 import로 나뉩니다. 메인 진입 시 전체 연구·논문·갤러리 데이터를 한꺼번에 내려받지 않습니다.

## 출력

`scripts/build.tsx`가 Vite의 브라우저 번들을 만든 뒤 React 서버 렌더러로 11개 HTML 문서를 출력합니다. 브라우저의 `hydrateRoot`가 같은 트리를 연결합니다. 본문은 초기 HTML에도 들어 있으며 기존 `.html` 주소와 정적 호스팅을 유지합니다. [React 공식 hydrateRoot 문서](https://react.dev/reference/react-dom/client/hydrateRoot)를 따릅니다.

소개서 2개는 독립 파일 요구를 유지하기 위해 `scripts/documents.ts`에서 원래 템플릿과 자산을 내장해 생성합니다. 개발 서버에서도 같은 독립 문서를 제공합니다.

## 소스와 결과 분리

`public/`은 자산 원본, `dist/`는 생성 결과입니다. `npm run build`는 이전 통합 폴더나 Google Sites 코드를 읽지 않습니다. 이전 Python 생성기는 `legacy/`의 참고 자료로만 보관하고 빌드에서 사용하지 않습니다. `source/` 원문은 내용 누락 검증용 근거입니다.

## 검증

TypeScript 검사와 빌드, 원문 내용·사진·영상·메뉴·링크 검사, 전환 전후 13개 문서의 본문·미디어·앵커 대조를 수행합니다. 메뉴 열기·연도 하위 메뉴·멤버 구분·사진 확대·이전/다음·모바일 레이아웃은 브라우저에서 확인합니다.
